# AI-Ready Design Systems

A white-label Claude plugin that acts as a Brand & Design System Architect — setting up two-tier design systems, generating DTCG-format design tokens, producing tone-aware UX copy, and auditing assets for brand compliance. Built to be deployed once and customized per client.

**Author:** Kelwadis Butler

**License:** MIT  
**Repository:** https://github.com/kelwadis-commits/AI-Ready-Design-Systems

## What this plugin does

This plugin operates across two design system tiers:

**Tier 1 — Marketing Design System** governs all outward-facing brand expression: ads, emails, landing pages, social, print.

**Tier 2 — Product Design System** governs in-product UX: web app, mobile app, component library, data visualization.

Both tiers draw from the same brand strategy and token source of truth. The plugin keeps them visually coherent and functionally distinct.

## Skills (v0.1.0)

### system-setup
Sets up a design system from scratch. Recommends a base component library, generates a DTCG-format token file, and produces a Figma variable spec.

Trigger with: "set up my design system", "what base system should I use", "generate a token file", "create Figma variables"

### copy-generation
Writes tone-aware UX and marketing copy anchored to brand voice. Covers empty states, error messages, CTAs, onboarding flows, transactional email, push notifications, tooltips, and more.

Trigger with: "write copy for", "error message for", "what should this button say", "onboarding copy", "empty state"

### token-update
Makes targeted changes to an existing DTCG token file while preserving the alias architecture. Explains downstream Figma variable impact for every change.

Trigger with: "update my colors", "change the type scale", "edit my tokens", "the brand color changed"

### system-audit
Audits a design, copy block, or asset against the brand strategy and token system. Classifies findings by severity (Critical / High / Medium / Low) and outputs specific, actionable fixes.

Trigger with: "is this on brand", "audit this", "brand review", "token compliance check", "does this follow the system"

### asset-generation
Presents 2–4 wireframe options for any product or marketing screen, injects the brand system (tokens, copy, imagery direction), and generates a Figma Plugin API script that builds the full-fidelity design inside Figma with variables wired. Covers checkout flows, onboarding, auth, dashboards, empty states, settings, landing pages, and email campaigns.

Trigger with: "wireframe a checkout flow", "design an onboarding screen", "show me options for my dashboard", "create a landing page", "push this to Figma", "generate a [screen name] screen"

**Figma plugin output:** The skill generates a `figma-plugin.js` script. Paste it into Figma's plugin runner (Menu → Plugins → Development → New Plugin → Run once) and it builds the screen directly in your file with color, spacing, and radius variables bound to your Token System collection.

## Setup

### 1. Install the plugin

In Claude Cowork, drag and drop `ai-ready-design-systems.plugin` into the plugins panel, or install from GitHub via the plugin manager.

### 2. Connect Figma (required for Figma-integrated workflows)

Generate a Figma personal access token:
1. Go to https://www.figma.com/developers/api#access-tokens
2. Create a token with read access to your files
3. Set it as an environment variable: `FIGMA_API_TOKEN=your_token_here`

The `system-setup`, `token-update`, and `system-audit` skills will automatically use the Figma MCP when a Figma URL or file key is provided.

### 3. Run system-setup for a new client

Start every new client engagement with the `system-setup` skill. It will:
- Ask for a brand brief
- Recommend a base design system
- Generate the plugin configuration block (the master reference for all outputs)
- Generate a seed token file
- Produce a Figma variable spec

## White-label customization

This plugin is designed to be deployed per client. Each client gets their own plugin configuration block — generated by `system-setup` and stored in the conversation — which controls all plug points.

### Pluggable components

| Plug point | Default | How to change |
|---|---|---|
| Base design system | Radix + shadcn/ui (web) | Update `product_tier.base_design_system` in config |
| Icon library | Heroicons | Update `brand_tier.icon_library_override` in config |
| Font system | Google Fonts | Update `brand_tier.font_system_override` in config |
| Asset / image library | Unsplash | Update `brand_tier.asset_library_override` in config |
| Data viz library | Recharts (web) | Update `product_tier.data_viz_override` in config |

### Client configuration block template

When starting a new client, generate this block via `system-setup` and keep it in the conversation:

```json
{
  "project": "Client Name",
  "brand_tier": {
    "icon_library": "heroicons",
    "icon_library_override": null,
    "font_system": "google-fonts",
    "font_system_override": null,
    "asset_library": "unsplash",
    "asset_library_override": null
  },
  "product_tier": {
    "base_design_system": "radix-shadcn",
    "token_format": "dtcg-json",
    "platforms": ["web", "mobile"],
    "data_viz_library": "recharts",
    "data_viz_override": null
  },
  "brand_strategy": {
    "status": "not_started",
    "source_file": null
  },
  "copy_mechanics": {
    "voice": null,
    "tone_rules": null,
    "reading_level": null
  }
}
```

## Contributing

This plugin is designed for iterative improvement. To contribute:

1. Fork the repository
2. Make changes to the skill files or references
3. Test by loading the updated `.plugin` file in Claude Cowork
4. Submit a pull request with a clear description of what changed and why

The most valuable contributions are to the reference files — the richer the token architecture, copy mechanics catalog, and audit rubric, the better the plugin performs across client engagements.
